`Components` is the last layer of the theme. It gives each component its own named colors — the background of a solid button, the border of a focused input, the track of a checked switch — and, for controls, its corner radius.

Components read this layer, never [colors](/docs/foundations/colors) or the [palette](/docs/foundations/tokens/palette) directly.

## Why a separate layer

Say a button reads a semantic color directly:

```tsx
backgroundColor: colors.primary.default;
```

Now you want blue buttons, and nothing else should change. You have two bad options:

- change `primary.default`: selected chips, switches and checkboxes turn blue too;
- hardcode a color in the button file: dark mode stops following.

With component tokens, the button reads `button.solid.default.background`. You point that one token to another semantic color, and only the button changes. Dark mode still works because the value still comes from `ThemeColors`.

Switch between the default and the custom button below. The checkbox and the switch keep the primary color, and the link and the focused input stay blue; only the solid button follows the change.

<ComponentTokenPreview />

The layer also:

- puts every component color in one file, instead of spread across dozens of components;
- keeps the `stylesheet`, `unistyles` and `tailwind` variants identical, since all three read the same value.

## What goes in

Component tokens hold what a theme changes: the **colors**, which change between light and dark or with your brand, and the **radius** of controls, which sets the character of an app.

| In `Components`                                                 | Elsewhere                                                                          |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Background, foreground, border, icon, placeholder, track, thumb | Heights, padding, font sizes: read from [tokens](/docs/foundations/tokens)         |
| One value per variant and state                                 | Minimum tap target (44pt): [metrics](/docs/foundations/tokens/metrics)             |
| `radius` of Button, IconButton, FloatingButton, Chip, Input and SegmentedControl | State logic, gestures, animation: [core](/docs/core) and [hooks](/docs/hooks) |

## Structure

Every token follows the same path:

```text
<component>.<variant>.<state>.<property>
```

| Segment     | Rule                                                                   | Examples                                                                                   |
| ----------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `component` | camelCase, same name as in the registry                                | `button`, `iconButton`, `segmentedControl`                                                 |
| `variant`   | The values of the `variant` prop. Components without one use `default` | `solid`, `outline`, `ghost`                                                                |
| `state`     | A closed list, always starting with `default`                          | `default`, `pressed`, `focused`, `checked`, `invalid`, `disabled`                          |
| `property`  | A shared vocabulary                                                    | `background`, `foreground`, `border`, `placeholder`, `icon`, `indicator`, `track`, `thumb` |

States other than `default` only list what changes. A missing property falls back to `default`: a pressed outline button keeps its border and text color and only changes its background.

```ts title="theme/components/button.ts"
type ButtonColors = {
	background?: string;
	foreground: string;
	border?: string;
};
type ButtonStates = States<ButtonColors, "pressed" | "disabled">;

export type ButtonTokens = {
	/** Corner radius. `tokens.radius.full` makes a pill. */
	radius: number;
	solid: ButtonStates;
	outline: ButtonStates;
	ghost: ButtonStates;
};
```

`States` comes from the theme: `default` is complete, every other state is a `Partial` of it. `radius` sits next to the variants, since every variant shares it.

## One file per component, inside the theme

Each component brings its tokens in its own file. `axiom add button` copies it to `theme/components/button.ts`, not next to the component.

It lives there because the theme is its only reader: a component never imports its own tokens file, it reads `components.button` from `useTheme()`. Keeping it in the theme means the foundations never import from the components layer, and everything you tune in a theme sits in one folder.

The file exports a pure function of the semantic colors and the tokens:

```ts title="theme/components/button.ts"
export const buttonTokens = (
	colors: ThemeColors,
	tokens: Tokens,
): ButtonTokens => ({
	radius: tokens.radius.md,
	solid: {
		default: {
			background: colors.primary.default,
			foreground: colors.primary.on,
		},
		pressed: { background: colors.primary.pressed },
		disabled: {
			background: colors.border.default,
			foreground: colors.content.disabled,
		},
	},
	outline: {
		default: {
			background: colors.background.default,
			foreground: colors.content.default,
			border: colors.border.default,
		},
		pressed: { background: colors.background.subtle },
		disabled: {
			foreground: colors.content.disabled,
			border: colors.border.subtle,
		},
	},
	ghost: {
		default: { foreground: colors.content.default },
		pressed: { background: colors.background.subtle },
		disabled: { foreground: colors.content.disabled },
	},
});
```

Rules:

- The function is pure. It reads `colors` for colors and `tokens` for shape. Never write raw values or palette steps in it.
- Never branch on the scheme (`if (dark)`). If a component needs a different value in dark mode, that difference belongs in `ThemeColors`.

## `components(colors, tokens)`

`theme/components/index.ts` gathers every tokens file of the project. You don't write it by hand: `npx axiom add <component>` copies the tokens file into the folder and registers it between two pairs of markers.

```ts title="theme/components/index.ts"
// axiom:imports:start
import { bottomSheetTokens } from "./bottom-sheet";
import { buttonTokens } from "./button";
// axiom:imports:end

export const components = (colors: ThemeColors, tokens: Tokens) => ({
	// axiom:components:start
	bottomSheet: bottomSheetTokens(colors, tokens),
	button: buttonTokens(colors, tokens),
	// axiom:components:end
});

export type Components = ReturnType<typeof components>;
```

- The key is the component name in camelCase, the function is `<key>Tokens`.
- The CLI only adds missing lines, and only when the tokens file is in the project. It never removes or rewrites a line.
- Keep the markers. Without them, `add` stops and asks you to copy the theme again. It stops too when `components` still takes only `colors`, as in themes copied before shape tokens.
- Removing a component: delete its two lines, then `theme/components/<name>.ts` and the component itself.

`components` is called once per color scheme:

```ts title="theme/theme.ts"
export const light = {
	tokens,
	colors: lightColors,
	components: components(lightColors, tokens),
} satisfies Theme;
export const dark = {
	tokens,
	colors: darkColors,
	components: components(darkColors, tokens),
} satisfies Theme;
```

## In each styling variant

The values are the same; only the way components read them changes.

```tsx title="stylesheet"
const theme = useTheme();

<Pressable
	style={{ backgroundColor: theme.components.button.solid.default.background }}
/>;
```

```tsx title="unistyles"
const styles = StyleSheet.create((theme) => ({
	solid: { backgroundColor: theme.components.button.solid.default.background },
}));
```

```css title="tailwind"
/* Each token becomes a CSS variable, one set per scheme */
--button-solid-default-background: var(--primary-default);
```

```tsx title="tailwind"
<Pressable className="bg-button-solid-default-background active:bg-button-solid-pressed-background" />
```

## Customizing

Edit the tokens file of the component. It belongs to your project, like the component itself:

```ts title="theme/components/button.ts — blue pill buttons" {1,4-5}
radius: tokens.radius.full,
solid: {
  default: {
    background: colors.content.link,
    foreground: colors.content.inverse,
  },
  pressed: { background: colors.content.link },
},
```

Pick the layer that matches the scope of the change:

| You want to change                               | Edit                                       |
| ------------------------------------------------ | ------------------------------------------ |
| One component                                    | Its tokens file (`theme/components/button.ts`) |
| Every action (buttons, selected and checked controls) | [`primary`](/docs/foundations/colors#primary) |
| A role across the app (every border, every link) | [`ThemeColors`](/docs/foundations/colors)       |
| The brand hue or a step everywhere               | The [palette](/docs/foundations/tokens/palette) |

`npx axiom add button` asks before overwriting a tokens file you changed.
