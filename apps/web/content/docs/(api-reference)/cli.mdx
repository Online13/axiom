The CLI copies source files into your project. It is the only thing Axiom publishes, and it never becomes a runtime dependency of your app: once the files are copied, your app doesn't need it.

## init

```npm
npx axiom init
```

Sets up a project for Axiom:

1. Asks for the styling tool: `stylesheet`, `unistyles`, `nativewind` or `uniwind`. Only the ones the registry has a variant for are offered.
2. Checks that `tsconfig.json` resolves the aliases, and offers to add the missing `paths` entries (see [Aliases](#aliases)).
3. Copies the foundations (theme, tokens, `light` / `dark`) and the headless core.
4. Asks, then installs the styling dependency and what the copied files need.
5. Writes `axiom.json`, with everything it copied listed in `items`.

Nothing is copied before step 2 passes: a project with half its aliases resolved is worse than one with none.

| Option             | What it does                                                                 |
| ------------------ | ---------------------------------------------------------------------------- |
| `--styling <tool>` | Answers the styling question, for a script or a CI job.                      |
| `--install`        | Installs without asking.                                                     |
| `--no-install`     | Prints the install command instead of running it.                            |
| `--force`          | Sets up a project that already has an `axiom.json`. Existing files are kept. |

### Aliases

Components are imported through an alias, so `init` resolves each one through the `paths` of your `tsconfig.json` before copying anything. When an alias doesn't resolve, it shows the entry it would add:

```txt title="Terminal" noCopy
tsconfig.json doesn't resolve @/theme, @/components/core, @/hooks, @/components/ui, @/components/compositions, @/components/blocks.
Add "@/*": ["./src/*"] to its "compilerOptions.paths"? [Y]es [n]o
```

Answer `n`, or keep a `tsconfig.json` the CLI can't rewrite safely — one with comments — and it asks for aliases your project already resolves instead.

### Installing

Before installing anything, `init` and `add` list the packages and ask. Answer yes and the CLI says what it is installing, with the command it runs:

```txt title="Terminal" noCopy
Install react-native-reanimated, react-native-gesture-handler? npx expo install react-native-reanimated react-native-gesture-handler
◇ Installing react-native-reanimated, react-native-gesture-handler
  npx expo install react-native-reanimated react-native-gesture-handler
```

Answer no and it prints the command instead. `--install` skips the question, `--no-install` answers no. Without a terminal to ask, `init` installs and `add` prints the command.

The CLI uses the package manager of your project, from its lockfile, and goes through `expo install` when the project has Expo, so the versions match your SDK.

## add

```npm
npx axiom add bottom-sheet
```

Adds a component to your project. The CLI:

- copies the variant that matches your configured styling;
- copies missing internal dependencies (`portal`, `overlay`, `tappable`…);
- installs third-party packages such as Reanimated or Gesture Handler;
- never overwrites an existing file without asking (see [Existing files](#existing-files));
- registers the component's tokens in the theme, if it has any (see [Component tokens](/docs/foundations/component-tokens#componentscolors));
- adds the component and every internal dependency it copied to `items` in `axiom.json`.

Internal dependencies are resolved as a graph. Adding `bottom-sheet` also brings in what it relies on, and skips anything already in your project:

```text
     bottom-sheet
          │
     ┌────┴────┐
     ↓         ↓
  portal    overlay
```

Names are plain component names. A component that is one file stays one file; one that brings a hook or a subcomponent gets a folder with an `index.ts`:

```npm
npx axiom add button         # → components/ui/button.tsx
npx axiom add bottom-sheet   # → components/ui/bottom-sheet/
```

```text
components/ui/
├── button.tsx
└── bottom-sheet/
    ├── bottom-sheet.tsx
    ├── bottom-sheet-root.tsx
    ├── use-bottom-sheet.ts
    └── index.ts          # so "@/components/ui/bottom-sheet" resolves here
```

Either way you import it the same: `import { BottomSheet } from "@/components/ui/bottom-sheet"`. Its [tokens](/docs/foundations/component-tokens) go to `theme/components/`, not here.

### Existing files

Copied files belong to your project, so `add` protects your changes. A file identical to the registry is skipped silently. When a file differs:

| File                                                                                           | What happens                                                                                                 |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| A file of the component you named                                                              | The CLI asks, per file: keep yours, overwrite it, overwrite all of the remaining ones, or keep all of yours. |
| A file of an internal dependency already in your project                                       | Kept. `add button` never touches your `tappable.tsx`. Name the dependency to update it: `add tappable`.      |
| A file your project owns once created, like the [icon registry](/docs/components/icon#the-registry) | Kept, always.                                                                                                |

```npm
npx axiom add button --overwrite
```

`--overwrite` replaces the files of the components you named without asking. Dependencies and owned files are still kept, and theme files (`theme/`, including each component's tokens) are still asked about, since that is where you customize them. Without a terminal to ask in, they are kept.

### Icons

The first item that needs icons asks where they come from (`expo-symbols` or `custom`) and saves the answer as [`icons`](/docs/configuration#icons). Pass `--icons <source>` to answer without a prompt. When a component draws icons your registry doesn't have, `add` lists them. See [Icon](/docs/components/icon#icons-that-components-need).

### Navigation

The first item that depends on the navigation library, like `use-overlay-back-handler`, detects it from `package.json` (`expo-router`, `react-navigation` or `react-native` without one) and saves it as [`navigation`](/docs/configuration#navigation). Pass `--navigation <library>` to override the detection.

Without a terminal (CI, a script), nobody can answer: differing files are kept and the CLI lists them.

### Standalone

```npm
npx axiom add tab --standalone
```

For an app that already has its own design system and wants one component from the catalog. `--standalone` writes a single file that imports only React, React Native and the npm packages the component uses:

- the Axiom pieces it stands on (Tappable, Text, Icon, its hooks) are inlined;
- `useTheme()` is gone. The file declares a `theme` constant with the values of the light theme it reads, and each component's tokens are typed as in the registry;
- nothing else is copied, and `axiom.json` is neither needed nor written.

The component no longer follows a theme: light / dark and any restyling are yours to handle, in a file that is already yours. What Axiom still guarantees is the behavior: touch targets, gestures, states, safe areas, accessibility.

The file goes where its layer's alias resolves in `tsconfig.json`: `@/components/ui/tab.tsx` for a primitive. Without an `axiom.json`, pass `--styling stylesheet` or `--styling unistyles`, or answer the prompt. A component that draws icons carries its own icon registry, the `icons` object in the file, filled from the source you pick; add your icons there.

Components that render through a portal (Dialog, Menu, Bottom Sheet, Toast, Snackbar) aren't available standalone yet: a portal needs a host mounted at the root of the app.

## fetch

```npm
npx axiom fetch
```

Copies every item listed in `items` in `axiom.json`. Use it to set up a project with the same items as another one, or to restore files that were deleted.

For each item, `fetch` runs the same steps as `add`: it copies the variant for your `styling`, resolves internal dependencies, and installs missing npm packages. Files already in your project are skipped, so your changes are kept.

`fetch` isn't an update command. To get a newer version of a component, run `add` again and confirm the overwrite.

## Configuration

The CLI reads and writes `axiom.json` at the root of your project: styling variant, aliases, and the list of copied items. See [Configuration](/docs/configuration).
