## Where we are

The specification is done: every foundation, component, behavior and pattern is written down, with its API, its states and its tokens. Phase 1 turns that into code.

Every primitive of this phase now runs in code, along with tokens, theme and the six core pieces: Title and Text, the 33 atoms, the three molecules, Passcode and the five templates. All 45 entries with styling variants ship in both `stylesheet` and `unistyles`, with demo screens for each. What is left of the phase is the Tailwind variants, standalone mode, the theme builder and the CI. The first compositions and the first block are in progress.

## Phase 1: the foundation

### Styling variants

1. `stylesheet` for every item in this phase, with the behavior / style split in place. Shipped.
2. `unistyles` for all 45 entries with styling variants, with matching APIs and a complete demo app. Shipped.
3. `tailwind` (NativeWind / Uniwind), once the split is proven on the first two.

### Standalone mode

Not started, and important enough to land in this phase. Today a component arrives with everything it stands on: ask for Tab and you also get the theme, the tokens and the headless core it imports. That is the right default for an app built on Axiom, and the wrong one for an app that already has its own design system and wants a single component out of the catalog.

Standalone mode breaks that chain. `axiom add tab --standalone` writes one self-contained file: token values resolved inline, no `useTheme`, no import outside React Native and the component's own file. Nothing else is added to the project.

The trade is explicit. A standalone component no longer follows a theme, so light / dark and any restyling are the user's job, in a file that is already theirs to edit. What Axiom still guarantees is the behavior: the touch targets, the gestures, the states, the safe areas.

It belongs to phase 1 because it is a registry concern before a CLI one. Every entry needs to describe the theme-free form of its component, per styling variant, and that shape is much cheaper to settle now than to retrofit across `unistyles` and `tailwind` once they exist.

`useOverlayBackHandler` was not in the original plan: BottomSheet, Dialog and Menu need to close on a back gesture instead of leaving the screen, so the hook ships in three versions — `react-native`, `expo-router` and `react-navigation` — and `add` picks one from the project's `package.json`.

Two core entries were added along the way. OverlayStack lets BottomSheet, Dialog and Menu know what is open on top of them, so a sheet scales down when another opens over it. Haptics is a single `haptic()` function that switches, pickers and long presses call; it does nothing until the app [connects its own library](/docs/integrations/haptics).

### Tooling

- `registry.json` — shipped, 55 entries.
- CLI — `add` and `init` are shipped. `add` resolves internal dependencies, icon source and navigation, and has a `--watch` mode; `init` picks the styling, resolves the aliases against `tsconfig.json`, copies the foundations and the headless core, installs what they need and writes `axiom.json`. `fetch` is still to write.
- Standalone mode — not started. A theme-free form per registry entry and variant, then `add --standalone` to write it.
- Demo apps — shipped for the `stylesheet` and `unistyles` variants: one screen per documented item, in 9 groups from Foundations to Templates, and a light / dark switch. The NativeWind and Uniwind apps are scaffolded and fill in with the `tailwind` variant.
- Theme builder — public at `/theme-builder`: role overrides, presets, app and component previews, Google Fonts, and an export an agent can apply.
- Foundations screen — shipped: colors, typography, spacing, radius, icons, touch targets, states.
- CI — not started. Typecheck per variant, props parity between variants, lint, tests, builds.

## Phase 2: blocks

Complete sections of an app, built from primitives and compositions, once the system is stable. [Settings section](/docs/blocks/settings-section) comes first, in phase 1; then [authentication](/docs/blocks/authentication), [onboarding](/docs/blocks/onboarding), [monetization](/docs/blocks/monetization), [profile](/docs/blocks/profile) and [commerce](/docs/blocks/commerce).

## Later

- [Agent integration](/docs/agent): the CLI commands an agent needs to find, plan and verify a screen — `search`, `info`, `plan`, `doctor`, `--json` output — plus the AGENTS.md, skill and MCP entry points. Specified, not built: only `add` and `init` are available today.
- [Patterns](/docs/patterns): selection mode, search experience, async content state…
- More [hooks](/docs/hooks): hide-on-scroll, collapsible header, keyboard-aware behavior…
- CI on Android and iOS devices, screenshots, visual tests (including parity between styling variants), accessibility checks.
