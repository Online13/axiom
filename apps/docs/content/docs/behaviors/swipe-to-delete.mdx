A short swipe opens a Delete button, like any [swipe action](/behaviors/swipe-actions). A long swipe deletes the row directly: the button grows with the finger, a haptic marks the point of no return, and releasing removes the row. A snackbar then offers to undo.

Swipe a row a little, then all the way. Delete a second row while the snackbar is still there: the first delete is committed. Press Undo and the row comes back in place.

## When to use it

- Lists of items the user owns and removes often: messages, notifications, cart items, saved searches.
- Deletions that can be undone for a few seconds, because the server call can wait.

Don't use it when the delete can't be reverted, or deletes more than the row shows (a folder with its content, an account). Ask first with a [Dialog](/atoms/dialog) instead. And, like every swipe, keep another way to delete: a [long press](/behaviors/long-press) menu or an edit mode.

## How it works

`progress` is `|translateX| / rowWidth`. Two thresholds split the swipe:

| Zone | Release does | Feedback |
| --- | --- | --- |
| Under half the button (40pt) | Closes. | – |
| Button to 55% of the row | Opens on the Delete button. | – |
| Past 55% (**armed**) | Deletes. | Haptic when crossing, both ways. The button fills the row, its icon follows the row's edge. |

Crossing back under 55% before releasing disarms it: the user can change their mind until the last moment.

### Delete now, commit later

The row leaves the list immediately; the request waits for the snackbar.

```text
release armed ──► row slides out (200ms) ──► height collapses (220ms)
                                              │
                                    Snackbar "Deleted · Undo", 4s
                                              │
            ┌──────────── Undo ───────────────┼──────────── timeout ────────────┐
            ▼                                 │                                 ▼
  row expands back in place            another delete                  onDismiss('timeout')
  nothing was sent                  commits this one first            delete request sent
```

- **Optimistic removal.** The list updates right away, so the user can keep triaging.
- **One pending delete.** A new delete replaces the snackbar, which commits the previous one (`onDismiss` with `'replaced'`).
- **Commit on leave.** Leaving the screen or backgrounding the app commits what's pending.
- If the request fails, put the row back and show the error in a [Toast](/atoms/toast).

## Implementation

There is no separate hook: a `SwipeableRow` with `fullSwipe` on its trailing action, and a [Snackbar](/atoms/snackbar) for the undo.

| Library | Used for |
| --- | --- |
| `react-native-gesture-handler`, `react-native-reanimated` | The swipe, as in [swipe actions](/behaviors/swipe-actions). `progress` and the armed state are derived on the UI thread; `runOnJS` fires the haptic when it changes. |
| Reanimated layout animations | `exiting` slides the row out, `LinearTransition` on the list closes the gap. `entering` for the undo. |
| React state | The ids removed from the list but not committed yet, dropped on undo. |

### In a screen

```tsx title="Conceptual"
const [removed, setRemoved] = useState<string[]>([]);
const visible = messages.filter((m) => !removed.includes(m.id));

const remove = (message: Message) => {
  setRemoved((ids) => [...ids, message.id]);
  snackbar.show({
    message: 'Conversation deleted',
    duration: 'short',
    action: { label: 'Undo', onPress: () => setRemoved((ids) => ids.filter((id) => id !== message.id)) },
    // 'timeout', 'swipe' and 'replaced' (the next delete) all commit.
    onDismiss: (reason) => reason !== 'action' && api.deleteMessage(message.id),
  });
};

<SwipeableRow trailing={[{ key: 'delete', icon: 'trash', label: 'Delete', color: 'error', fullSwipe: true, onPress: () => remove(item) }]}>
  <Item>…</Item>
</SwipeableRow>
```

## Accessibility

- Add a "Delete" entry in `accessibilityActions` on the row.
- Announce the deletion and the undo: the snackbar is announced, and keeps its action focusable for its whole duration. Its duration is extended when a screen reader is on.
- The haptic isn't the only signal: the button changes shape when armed.
- With Reduce Motion on, the row disappears without sliding and the gap closes without animation.
