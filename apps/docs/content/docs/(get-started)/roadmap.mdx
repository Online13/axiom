## Where we are

The specification is done: every foundation, component, behavior and pattern is written down, with its API, its states and its tokens. Phase 1 turns that into code, starting with the `stylesheet` variant and the foundations.

<PhaseChecklist />

## Phase 0: specification

Done. The whole system exists on paper first — [foundations](/foundations), [core](/core), [hooks](/hooks), the [component catalog](/components), the [behaviors](/behaviors) and the [patterns](/patterns). Nothing gets built twice because the API was decided while writing it down.

## Phase 1: the foundation

### Styling variants

1. `stylesheet` for every item in this phase, with the behavior / style split in place.
2. `unistyles`.
3. `tailwind` (NativeWind / Uniwind), once the split is proven on the first two.

### Components

| Group | Items |

### Tooling

- `registry.json`
- CLI (`init`, `add`)
- Demo app: one screen per component, light / dark switch, side-by-side styling variants
- Foundations screen: colors, typography, spacing, radius, icons, touch targets, states
- CI: typecheck per variant, props parity between variants, lint, tests, builds

## Phase 2: blocks

Complete screens built with Axiom components, once the system is stable: [authentication](/blocks/authentication), [onboarding](/blocks/onboarding), [monetization](/blocks/monetization), [profile](/blocks/profile) and [commerce](/blocks/commerce).

## Later

- [Patterns](/patterns): selection mode, search experience, async content state…
- More [hooks](/hooks): hide-on-scroll, collapsible header, keyboard-aware behavior…
- CI on Android and iOS devices, screenshots, visual tests (including parity between styling variants), accessibility checks.
