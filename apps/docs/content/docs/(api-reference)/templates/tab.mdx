## Installation

```npm
npx axiom add tab
```

Also copies: [`icon`](/atoms/icon), [`badge`](/atoms/badge), [`text`](/atoms/text), [`tappable`](/core/tappable) and [`useControllableState`](/hooks/use-controllable-state). Installs `react-native-reanimated` and `react-native-gesture-handler`.

Colors come from `tab.{underline,pill}.{default,selected,disabled}` in the [component tokens](/foundations/component-tokens).

## Usage

```tsx
import { Tab } from '@/components/ui/tab';

<Tab value={section} onValueChange={setSection}>
  <Tab.Item value="all">All</Tab.Item>
  <Tab.Item value="unread">Unread</Tab.Item>
  <Tab.Item value="archived">Archived</Tab.Item>
</Tab>
```

## Props

### Tab

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `string` | — | Value of the selected tab in controlled usage. |
| `defaultValue` | `string` | — | Initial selection when the component owns its state. |
| `onValueChange` | `(value: string) => void` | — | Called after an enabled tab is pressed. Use it to swap nearby content, not to push a new screen. |
| `variant` | `'underline' \| 'pill'` | `'underline'` | Uses an indicator below the label or a filled capsule behind it. |
| `scrollable` | `boolean` | `false` | Lets items keep their natural width and scroll horizontally. Use it when four or more labels do not fit. |
| `swipeEnabled` | `boolean` | `false` | Also switches tab on a horizontal drag across the panels. Requires `Tab.Panel` children. |
| `children` | `ReactNode` | — | Two or more `Tab.Item` elements, and one `Tab.Panel` per item when the screen owns its content. |
| `style` | `StyleProp<ViewStyle>` | — | Extra styles for the tab list. |

### Tab.Item

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `string` | — | Stable identifier returned through `onValueChange`. |
| `children` | `ReactNode` | — | Short label. One or two words scan best. |
| `icon` | `IconName \| ReactNode` | — | Optional icon before the label. Avoid icons when every tab is already clear in text. |
| `badge` | `number \| string \| boolean` | — | Count, short status or dot next to the label. |
| `disabled` | `boolean` | `false` | Blocks selection and exposes the disabled accessibility state. |
| `accessibilityLabel` | `string` | label text | Spoken label when the visible text needs more context. |

### Tab.Panel

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `string` | — | Value of the `Tab.Item` this panel belongs to. |
| `children` | `ReactNode` | — | Content shown while that tab is selected. |
| `style` | `StyleProp<ViewStyle>` | — | Extra styles for the panel. |

The indicator travels on a spring, and lands without animating the first time: it has nothing to travel from until the items have been measured. Reduced motion moves it without animation.

`Tab` sets the tab list, tab and selected accessibility roles. Panels are optional: without them `Tab` is only a row, and the screen decides what to render under it.

## Swipe to switch

`swipeEnabled` changes what the component is. A tab row is a set of buttons; a swipeable tab row is a pager whose tabs are a map of where the finger can go. Both are correct, and which one a screen wants is not something the component can guess — so it is a choice, off by default.

Turn it on when the tabs are peers over the same kind of content, the way a feed, an inbox or an order list reads. Leave it off when the panel owns the horizontal axis — a carousel, a pannable chart, rows with [swipe actions](/behaviors/swipe-actions) — or when the panels are unrelated enough that landing on the next one by accident is a mistake rather than a shortcut.

The markup is the same either way: panels are declared with `Tab.Panel`, next to the items.

```tsx
<Tab swipeEnabled value={section} onValueChange={setSection}>
  <Tab.Item value="all">All</Tab.Item>
  <Tab.Item value="mentions">Mentions</Tab.Item>

  <Tab.Panel value="all"><Feed /></Tab.Panel>
  <Tab.Panel value="mentions"><Mentions /></Tab.Panel>
</Tab>
```

With `swipeEnabled` off, the selected panel is rendered and the others are not; the layout is the row plus its content. With it on, `Tab` fills its parent and lays the panels side by side in a row that follows the finger, so it needs a bounded height — inside a [Scaffold](/templates/scaffold) body, that is already the case.

<TabSwipeFrames />

The pages and the indicator read one progress value. The indicator is not animated toward the new tab on release: it is already where the finger left it, and only finishes the last part of the travel.

<TabSwipeMachine />

- The drag activates past 10pt horizontally and gives up on vertical movement, so a list inside a panel still scrolls.
- On release, velocity decides first: a flick over 500pt/s switches tab whatever the distance. Otherwise a drag past a third of the width switches, and anything shorter returns.
- `onValueChange` fires on release, not when the travel ends. The screen sees the new value while the pages are still moving.
- At the first and last panel, movement outward meets resistance and springs back. The pager does not wrap.
- Pressing an adjacent tab animates the pager. Pressing a farther one jumps, rather than flying through the panels in between.
- Reduced motion leaves dragging untouched — it is direct manipulation, not animation — and makes the settle and the tab-press travel instant.
- A panel mounts the first time it is reached and stays mounted. The panel next to the finger mounts as soon as the drag starts, so it is never blank while entering.
- Panels that are off screen are hidden from the screen reader, which switches tab by pressing them. Nothing in the behavior is gesture-only.
- A horizontal gesture that starts inside a panel wins: the pager waits for it to fail before claiming the drag.

With `scrollable`, the item row scrolls the selected item into view as the pager moves, not after it lands.

## Use cases

### Switching one data view

Tabs work when the content changes but the screen purpose stays the same. Keep the filter state local to the screen.

### Categories that need horizontal scrolling

When labels cannot fit without shrinking, let the row scroll. The selected tab should be brought into view after selection.

```tsx
  {categories.map((item) => <Tab.Item key={item.id} value={item.id}>{item.label}</Tab.Item>)}
</Tab>
```

### Compact mode switch with pills

The pill variant works for a short, local mode switch. For two or three equally sized options inside a form, prefer [SegmentedControl](/atoms/segmented-control).
