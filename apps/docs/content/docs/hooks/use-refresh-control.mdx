<Callout title="Draft">The API shown here is conceptual and may change.</Callout>

The hook behind [Pull-to-refresh](/behaviors/pull-to-refresh). That page explains the statuses, the resistance, the platform differences and accessibility. This one covers the API.

## Installation

```npm
npx axiom add use-refresh-control
```

Installs: `react-native-reanimated`, `react-native-gesture-handler`.

## Usage

```tsx title="Conceptual"
import { FlatList } from 'react-native';
import { useRefreshControl } from '@/hooks/use-refresh-control';

function Inbox() {
  const { data, refetch } = useMessages();
  const refresh = useRefreshControl({ onRefresh: refetch });

  return (
    <View style={{ flex: 1 }}>
      <PullIndicator control={refresh} />
      <FlatList data={data} renderItem={renderMessage} {...refresh.scrollProps} />
    </View>
  );
}
```

`onRefresh` can return a promise. The status stays `refreshing` until it resolves or rejects, so there is no `refreshing` flag to keep in sync. The hook doesn't catch the error: handle it in `onRefresh`, for example with a [Toast](/atoms/toast).

### A custom indicator

`progress` and `distance` are Reanimated shared values. The indicator reads them on the UI thread, with no React render per frame:

```tsx title="Conceptual"
function PullIndicator({ control }: { control: RefreshControl }) {
  const { progress, distance, status } = control;

  const style = useAnimatedStyle(() => ({
    height: distance.value,
    opacity: progress.value,
    transform: [{ rotate: `${progress.value * 180}deg` }],
  }));

  return (
    <Animated.View style={[styles.indicator, style]}>
      {status === 'refreshing' ? <Spinner /> : <Icon name="arrow-down" />}
    </Animated.View>
  );
}
```

`status` is React state. It changes a few times per pull, so it's fine to switch icons on it. Use the shared values for anything that moves with the finger.

### Refresh from code

`refresh()` goes straight to `refreshing` and opens the list to `threshold`, like a released pull. Use it for a retry button, a screen focus, a push notification, or the accessible refresh button. It does nothing while a refresh is already running.

```tsx title="Conceptual"
<Button onPress={refresh.refresh}>Retry</Button>
```

## Options

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `onRefresh` | `() => Promise<unknown> \| void` | — | Called on release past the threshold, or by `refresh()`. |
| `threshold` | `number` | `64` | Distance in pt that arms the refresh. Also the height held while refreshing. |
| `maxDistance` | `number` | `160` | Limit of the rubber band. |
| `minDuration` | `number` | `500` | Minimum time in ms spent in `refreshing`, so a fast request doesn't flash the indicator. |
| `enabled` | `boolean` | `true` | Turns the pull off, for example while the first page loads. |
| `onArmed` | `() => void` | — | Called once per pull when the status becomes `armed`. A good place for a light haptic. |

## Return value

| Key | Type | Description |
| --- | --- | --- |
| `status` | `'idle' \| 'pulling' \| 'armed' \| 'refreshing' \| 'settling'` | Current status. React state. See [statuses](/behaviors/pull-to-refresh#how-it-works). |
| `refreshing` | `boolean` | `true` while `status` is `refreshing`. |
| `distance` | `SharedValue<number>` | Current pull distance in pt, after [resistance](/behaviors/pull-to-refresh#resistance). |
| `progress` | `SharedValue<number>` | `distance / threshold`, from `0` to `1`. |
| `refresh` | `() => Promise<void>` | Starts a refresh without a pull. |
| `scrollProps` | `object` | Props to spread on the `ScrollView`, `FlatList`, `SectionList` or `FlashList`. |
